## 3. 写明的选择（回显，可更正）

1. **壳层板的格。** 以 B 段为矩阵：33 行 × 浅色夜间 = 66 格，先列浅色 33 格再列夜间 33 格（第一批五板同序），fill / ink / surface 逐字取 build-shell2.mjs matrixRows，后缀色与遮罩用字面量 #2c63c8、rgba(22,21,15,.2)。生成后 66 个 expect 与 B 段 data-cr 逐格相等，豁免与 B 段 ex 标记一致。
2. **命名。** 26 行在 07a A 段有 data-cell 名，直接沿用（52 格）。B 段独有的 7 行取新名：`brand-mark`、`brand-focus`、`bell-hover`、`panel-edge`、`it-chev`、`sheet-row`、`scrim-paper`。
3. **标按钮 hover / open 两行。** 07a 在完整菜单屏仍把这两格叫 `brand-word-*`、`brand-suffix-*`（值 14.70 / 14.14、4.53 / 3.07）。data.mjs 要求 cellId 唯一，所以契约键是 `brand-word-open-*`、`brand-suffix-open-*`，`id` 仍是 07a 名；story 的 data-cell 取 `id` 加主题后缀，于是这两格与 idle 格同名，和板上一样。夜间 3.07 因此落进壳层门 `pendingBelowMinimum` 的 `brand-suffix-n`。matrices.json 的 description 已写明这条，第一批五板 `cellId` 仍等于 `id` 加后缀。
4. **夜间 TMS 后缀的红格。** `brand-suffix-n`（3.33）、`brand-suffix-open-n`（3.07）、`lk-em-n`（3.13）都记 exempt false，与板和 P4 的约定一致。
5. **contract-proof 的壳层板比对。** 按位置比 B 段（data-cr 差 0、ex 与豁免一致、同一行浅色夜间同 id）；07a 名在 A 段出现的格，A 段须有一处 data-expect、data-kind 都相等；A 段命名格数须为 52（`EXPECTED_SHELL_NAMED`），改名会被抓到。新增导出 `SHELL_BOARD`、`EXPECTED_SHELL_NAMED`、`shellBoardMatrix`。第一批五板的判定不变。
6. **story 的形态。** 两块叠放（MatrixBoard），没有 `data-shell` 壳根，屏幕留给另外四个壳层 story。画布上：标按钮 idle、hover、focus；ShellPins 四项（选中、静止带箭头、悬停、下拉已开）；铃铛静止与悬停、头像，取自 ProductShell 自身标记里的两个按钮。纸面上：ShellMenu 面板、ShellDropdown（固定项 schedule 的 aria-controls 指向它）、390 × 320 的 `contain: layout` 手机块，里面是 Sheet 与遮罩下的 Surface 文字。浮层只改定位：面板与下拉的 style 改为 `position:relative;top:0;left:0;margin-top:0`，下拉服务端的 `visibility:hidden` 随之去掉，其余只加格属性。
7. **标按钮 open 用 hover 预览。** open 对与 hover 对同值（都是 3.5% 墨洗与 ink），用 hover 预览就不必再给页面加 `aria-expanded="true"`。固定项的 open 只能是真状态，页上因此多 2 个（问题 3）。
8. **探针。** `srch-ph`、`drop-srch` 用 ph；`brand-focus` 用 shadow（第一批的词，壳层门还没有，见问题 1）。
9. **文案。** 标题与描述五语齐，四语值不与同语言其它键同值；菜单、固定项与纸内文字全部复用内容字典已有词条，没有新增内容字典键；`<code>` 新增 6 个机器词（idle、pins、cluster、expanded、drop、sheet）登记在 ledger 的 matrixMachineWords。
