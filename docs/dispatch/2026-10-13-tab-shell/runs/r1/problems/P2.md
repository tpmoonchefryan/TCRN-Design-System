# P2 问题（INIT-016 R1 · W1，见红只记）

同一根因算一条。每条写：现象、证据、持有者或建议去向。

1. **token-extension-proof 在本包分支上红一条（预期，随合入清零）。** 现象：`unresolved public token reference: --tcrn-shell-pinb`。证据：sub123-token-extension.log、sub127-token-extension.log，退出 1，问题只此一条。原因：图钉槽按 C-2 名表引用 `--tcrn-shell-pinb`，该 token 由同波 P1a（SUB-113）新增。去向：P1a 合入后复跑即应为 0；若合入后仍红，说明 C-2 名表与 P1a 实际变量名不一致，退回拆分。

2. **Icon 板文字仍写 37 件。** 现象：build-icon.mjs 里硬写「名册 tcrnIconNames · 37 件」「28 件现有加 9 件新增」「名册从 28 件扩到 37 件」「tcrnIconNames 37 件」「37 件逐个绘制」等，A 段网格现在画 38 枚。同板「绘制规则」写「禁止：……填充色块……」，与 pin 的实心态（只在已固定时填充图钉本体）字面相抵；板上也没有画出实心态。证据：build-icon.mjs 第 76、181、187、202–205、110 行；不在 P2 文件集。去向：SUB-133（P11 W7，Icon 板的下一持有者）改 build-icon.mjs 的文字并决定实心态的展示；绘制规则与实心态的措辞如需裁定，列给 Owner。

3. **成品板重生会改写板内 token 块（改动前已有的漂移）。** 现象：在未改任何文件的树上重跑 build-icon.mjs 4280 与 make-standard.mjs，两块 Icon 板各有一行变化：板内 token 块的 `--mono` 多出 "Noto Sans SC"，并新增 `--r-paper`、`--rail-w`、`--rail-w-collapsed`、`--topbar-h`（共 85 字节）。证据：baseline-build-icon.log、baseline-make-standard.log（改动前），以及本包重生后的同一行。处置：本包只提交 A 段名册两行，token 块保留 HEAD 原样，所以这两块板对生成器仍差这一行，与改动前相同。去向：SUB-133 在 W7 统一重生（届时还会带上 P1a 的壳 token）；其余三块板这次重生字节不变。

4. **Storybook 与说明文字里的 37 件。** 现象：以下渲染或说明文字仍写 37 个图标：`apps/storybook/src/contract-stories/gplus/matrix-stories.tsx` 第 501 行、`apps/storybook/src/contract-stories/story-content.tsx` 第 1066 行、`apps/storybook/src/build/locales/storybook-locale-text.ts` 五语的 `story.icon-matrix.description`（第 138、320、502、684、866 行）、`apps/storybook/src/build/locales/storybook-content-text.ts` 第 528 行、`docs/design/gplus-2026-10/README.md` 第 14 行。均不在 P2 文件集。去向：请主线程按 packages.md 交给 story 文案与文档的持有者，改 38 时五语同改。

5. **icons-motion story 高度预算可能受影响（未测）。** 现象：`scripts/lib/story-budget.mjs` 记 icons-motion 高 2102，注释说图标样格渲染整个名册；名册多一枚，若样格换行，高度会变。本包没有跑 Storybook 的几何与预算门，结果未知。去向：跑 story 预算的持有者（SUB-134 或 SUB-140）在批末门里核对。

6. **生成物注释「names added in the G+ batch」。** 现象：contract-generate.mjs 写给 `tcrnIconNewNames` 的注释仍说 G+ 批，现在含顶带壳批的 pin。不影响门。去向：下一个改 contract-generate.mjs 的 Subtask 顺手改注释，或接受现状。

7. **壳层测量钩子与 NavItem 的接口缺口。** 现象：C-5 的行内图标 `data-guide="prail"`、文字 `data-text="prail"` 不在 NavItem 里；NavItem 的 props 落在链接上，可钉行的图钉是链接的兄弟，不是带 `data-shell-row` 的链接的后代。W2 的 P1b（SUB-116、SUB-118）不持有 Navigation.tsx，无法为 NavItem 加钩子。去向：P3 的测量库按类选择（`.tcrn-nav-item-row`、`.tcrn-nav-item .tcrn-icon`、`.tcrn-nav-item__label`），或由 Navigation.tsx 的下一持有者（SUB-119、SUB-120，W3）补钩子；二选一请主线程定。

8. **可钉行的标签没有单行截断。** 现象：`.tcrn-nav-item__label` 仍没有 nowrap、ellipsis、title（navigation 家族在 C7 豁免内），长名在可钉行里会折行。START 硬线要求导航项单行截断加 title。去向：SUB-124 / SUB-125（家族归位）或 SUB-116 的行样式；本包未扩大范围。

9. **触摸端图钉的可发现性。** 现象：判据只给热区 44；静止时图钉 opacity 0，触摸端没有 hover，未固定的行只有在获焦时才看得见图钉。去向：设计问题，建议与 SUB-126（Sheet）一起交 Owner 定触摸端是否常显。

10. **可钉行与旧侧栏的 O-1 负外边距。** 现象：`.tcrn-product-shell .tcrn-nav-item` 在桌面给链接左右各 -space-1 的外边距；可钉行放进旧侧栏时，链接会比行宽出 4。去向：SUB-119 撤 O-1 几何后自然消失；在此之前不要把可钉 NavItem 放进旧侧栏。

11. **静态预览态未接到可钉行。** 现象：图钉是 NavItem 内部元素，行的 hover 态与图钉的 hover 态都没有 `data-tcrn-preview-state` 入口（固定态可经 `pinned` 表达）。去向：SUB-136（shell-matrix 逐格 story）若要静态展示「项 · hover 图钉出现」，需由 Navigation.tsx 的持有者加入口。
