1. **局部门「Shell 两板逐字节不变」在本包改动前就红（预期外的前提失效，非抽模块引起）。**
   - 现象：`build-shell2.mjs final --h1 5324 --h2 4895` 之后，`git diff --exit-code` 对 `Shell.dc.html`、`Shell-2.dc.html` 退出 1，两板各差一行：第 69 行板内 token 块。
   - 证据：抽模块之前在未改的包树上跑同一命令，差异相同（`13-base-bs2.log`、`14-base-diff.txt`）；差异内容是 tokens.json 已有而板上没有的值：`--mono` 多 "Noto Sans SC"，新增 `--r-paper`、`--intro-*`、`--rail-w`、`--rail-w-collapsed`、`--topbar-h`、20 个 `--shell-*` 与 `--layout-content-max-w`（P1a、P6 与更早的契约改动）。与 P2 问题 3 同一根因。
   - 本包的处置：两块 Shell 板一律 `git checkout` 复原，不提交；抽模块的守护改用「同一包树上，抽模块前后 final 输出逐字节相同」：`cmp` 两板均相同（`36-guard1.log`、`37-guard2.log`、`gate-final-shell-equivalence.log`）。字面门照跑并记录退出 1（`gate-final-shell-diff.log`）。
   - 去向（待定）：C-16 规定 Shell 两板任何包不改。要让字面门回绿，须由有权改这两块板的一方（设计会话或 Owner）决定是否按当前 token 块重生两板；不重生则此门恒红，建议把守护口径改为「改动前后输出相同」。
