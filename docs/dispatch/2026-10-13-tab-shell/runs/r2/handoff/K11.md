## 2. 写明的选择与回显项

1. `apps/storybook/src/build/shell-hydrate.tsx` 不在摘录的文件集里；派工通告（cross-notes K5 行）指明新屏加在它的屏表，ShellStoryScreenView 的页头层级也在这里，故改了它。屏表新增五屏，字段新增 `typed`（菜单词条名，取其当前语言标签的前 3/5、至少 2 字作已输入词，经 ProductShell `menuQuery` 渲染结果）与 `page`（`settings` / `roster`）。
2. 已输入屏 ts-search-l 输入「Contracts」的前缀（en「Contra」、zh-CN「合同」），五语都得到同一组 7 条结果；菜单保持展开（`menuOpen`），词受控、不接 `onMenuQueryChange`。
3. open-menus 的派生：页面上每个 `aria-expanded="true"` 的控件，其 `aria-controls` 指向的元素都在页上，且控件显示时它也显示，才计入期望数；不符的列在 `strayOpenMenus`。现读 14 = 14、游离 0。判定语义按 C-7「open-menus 改为从 DOM 派生」。
4. 地标名：文档壳 `landmarkLabel` 取 `shell.brand`（五语）；壳 story 每屏取屏名（同 contentLabel）；样板取原 landmarkLabel 加夜间后缀；AOS 两个实例取各自 contentLabel；契约证明框取「Package-backed AOS shell boundary」（已有五语），并补同名 contentLabel，因其默认内容区名与知识库演示壳重名。
5. 层级：文档壳保持纸内默认 h1；页内壳（壳 story 各屏、样板、AOS 实例、契约证明框）一律传 `headingLevel: 2`。浏览器证明里 page-has-heading-one 为 0。
6. 分类说明放在 `docMenuModel` 第二级分类条目的 `description` 上（K6 问题 2），smoke 的 categoryDescriptionCount 0 → 23（桌面、手机），browser-proof 的 categoryAriaFailures 全部 0。
7. 设置页与名册页：面包屑为「Talent Management System › Settings › Notification preferences」与「Talent Management System › Members and permissions › Roster」，全部取已有五语词；设置页为 SettingsLayout（两个分节 Tab、一行角色 Select、一个邮件通知 Switch），名册页为 SplitView（每人一行可换行，不用 TableShell：其列宽下限 160×3 会伸出 390 的纸）；页内区域名一律「屏名 · 词」，各屏不重名。名册人名沿用动作样板的三个非拉丁名。这两类屏不做板上收起屏的第三个固定项悬停改写。
