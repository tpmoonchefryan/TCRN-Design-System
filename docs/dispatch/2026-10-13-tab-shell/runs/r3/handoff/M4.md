## 4. 写明的选择与回显项（B 类，可事后更正）

1. **ShellMenu、ShellDropdown 各加了可选的 `landmarkLabel`。** SUB-184 的注意写着「不加新 prop」。判据①点名的四处地标在 ShellMenu 与 ShellDropdown 里，ProductShell 只能经 prop 把前缀传到它们；矩阵页上独立的 ShellMenu、ShellDropdown（浅色与夜间同页）也必须能取名，否则判据⑤的「下拉名」「Navigation」「Current location」各留节点。这个 prop 与 ShellPins、PageHeader 已有的 `landmarkLabel` 同名同义；ProductShell 的 prop 面没有因 SUB-184 增加。考虑过的两种替代：内部 context（矩阵上的独立件取不了名，⑤ 达不到）；在矩阵 story 里用标记编辑改 aria-label（文档里出现包件自己给不出的名字，是用局部覆盖盖住包件缺口）。
2. **头像菜单 dialog、切换产品 nav、顶带 header 也加前缀。** 判据①的列举没写这三处，但①说「壳内全部具名地标」、④要收集「全部带名地标」并断言互不相同；只差 landmarkLabel 的两个壳，header 名（含 moduleName）会撞。副作用：文档壳（page-template 传的 landmarkLabel 与 moduleName 都是品牌名）的 header 名变成「品牌名 · 品牌名 外壳控件」这一类重复说法，见问题文件第 7 条。
3. **显式 `contentLabel` 照原样，不加前缀。** 与 ShellPins 显式 `aria-label` 优先的写法一致；构图三的 smoke 断言读的就是显式名。
4. **TocRail 用 `aria-label` 取名，没用 `aria-labelledby`。** 静态页上 story 分别渲染，`useId` 的 id 在同页可能重复，指向别的标题。
5. **SUB-194 的 `asset.markId` 不是 logos2 文件名。** 注册表里 `markId` 是标的产品键（design-system、mana-orchestrate），判据期望的是 ds、mana。改写成 `tcrnProductMarks` 里该标的 `id`（新增模块内函数 `productMarkIdOf`，不导出）；产品键仍在 `data-product-id` 与 `data-product-mark`。brand-asset-source-proof 第 143 行的比对键同包改为 marks.json 里该产品的标 `id`（按 productId 查），字节比对不变，检查没有放宽（C-7 写明的 B 类）。
6. **token 名照 C-2 默认名，没有改名**：`shell.chevron`、`shell.locale-chevron`、`shell.mark-lg`。
