## 2. visual-proof 的 story 清单在按类运行时把构图三报成未映射（门判定缺口，超出 SUB-093 授权）

- 现象：`tests/storybook-visual-proof.test.mjs` 的「130-GWT2 on the built docs」红：`--kind matrix` 下 notInMap 为 `["icon-matrix", "composition-three-sample"]`，期望只有前者。npm 脚本 `storybook:visual-proof` 用 && 串联，所以退出码为 1，脚本段不跑。单跑脚本段（默认两类）是绿的。P0 那次看到的同一条红就是它，SUB-093 加映射行之后仍在。
- 原因：
  - `storyKind()`（`scripts/storybook-visual-proof.mjs` 约 188 行）只认十个固定 id，构图三判为 unknown。
  - `reconcileStories` 在任何 `--kind` 下都把 unknown 的 story 列进清单，而构图三的映射行 kind 是 sample，矩阵运行时不在范围内。
  - 结果是只要注册表里有构图三，手册里写的「只判矩阵行用 `--kind matrix`」那种运行就会红。
- 建议改法（任选其一，都要授权）：
  - storyKind 对不在固定 id 里的 story，按注册表类目取值（gplus-samples → sample，gplus-matrices → matrix），或按映射行的 kind 取值。要改 storybook-visual-proof.mjs 的判定逻辑，而 SUB-093 对该文件只授权改第 62–64 行注释。
  - 把构图三加进 `scripts/lib/storybook-routes.mjs` 的固定 id。不建议：会波及 fonts-render-proof、doc-sample-style-proof、GPLUS_FAMILIES、「十个 id」计数与「样板必测 rail / shellFrame」等断言；也和映射自己写的规则矛盾（构图三经 gplus- 类目进清单，不在约定 7 的十个 id 里）。所以本包没有动 storybook-routes.mjs。
- 测试没有改成两类运行：那样会盖住真实的门缺口。
