## 4. SUB-055 · 链接与 quiet 链接状态改走对表，焦点补透明 outline 回退（R2-5）

  - default：ink-d 为 acc，underline-d 为 acc-ul，edge-d 为 `0 0 #0000`；h 的 ink 与 underline 都是 acc-2；edge-f 为焦点环 `var(--focus)`。

## 5. SUB-058 · inputs-text 补只读获焦态（R2-6）

- **二选一：加 rf 元组，不取「把 f 排到 r 之后」。** 理由：f 的元组会把底换成 panel，排到 r 之后，获焦的只读框就变成可编辑框的样子，看上去像能输入。rf 只换边：r 的底（panel-2）与字色保留，边换成 f 的焦点环，所以获焦时仍看得出是只读。
- 契约：pairs.json 的 inputs-text 新增状态 `rf`（readonly-focus），条件为 `[readonly]` 或 `[aria-readonly="true"]` 加上 `:focus-visible` 或焦点预览态。ruleOrder 改为 h、f、r、rf、e、ef、x。default 变体的 rf 只声明 edge，值为 `inset 0 0 0 1px var(--acc),var(--focus)`。search 变体的 rf 回落到 default。
- 重生成：inputs.pairs.ts 增加 rf 声明和 rf 规则；actions.pairs.ts 与 matrices.generated.ts 只改了 contract-sha256 头。生成器不用改。矩阵逐格期望没有变化（契约里没有只读获焦的格），门也没改。
- Form.test.tsx 新增一条：先核对 rf 声明、规则次序（f < r < rf < e），以及 rf 规则只切换 edge；再把真实的只读 `Input`（焦点预览态）和整张表交给 jsdom 层叠，得到生效对 fill 为 `fill-r`、edge 为 `edge-rf`（焦点环）。作为对照，只读未获焦为 `edge-r`，可编辑获焦为 `edge-f`；把 rf 规则从表里删掉后，只读获焦退回 `edge-r`。
- 判据：达成。

## 6. §3.4 第 1 项回显（R2-6，与画板状态顺序不同）

画板的 inputs-text 是 r 盖住 f，只读框获焦时看不到焦点。本包按建议先做：加了 rf 元组，排在 r 之后，只读框获焦时显示焦点环，底与字色仍是只读态（WCAG 2.4.7）。画板没有重生成（见 problems/P2.md 第 3 条）。Owner 可事后更正，例如改为把 f 排到 r 之后，或者恢复画板顺序。

## 7. 本包另做的实施取舍（请留意）

- `tcrn-link--quiet` 现在是 `.tcrn-link` 的修饰类，要和 `tcrn-link` 一起用；单独写 `tcrn-link--quiet` 不再有样式。仓内没有单独使用的地方（组件、story、文档都没有）。对外说明可以在 SUB-087 改 CHANGELOG 时一并写。
- quiet 链接悬停的下划线偏移从 0.2em 变为链接统一的 2px，颜色从 brand-primary（即 acc）变为 acc-2，与判断写的 ink-h acc-2 一致。
- 新增生效对变量 `--tcrn-pair-underline`。状态规则不能写 text-decoration-color，链接下划线色只能走对表，所以需要这个变量。token-extension-proof 接受任意 `--tcrn-pair-*`。没有新增 pairs 元组名，rf 是 SUB-058 授权的那一个。
- numeral 的字号和行高引用 heading-2 的 token（值相同）。以后若 H2 改值而 numeral 不改，生成器会报值不一致，逼出一次取舍，不会静默跟着变。
- gplus-tokens.generated.ts 的头部现在列 typography.json，以后改 typography.json 的包会同时改写它的 contract-sha256 行。R2 跨包约定第 7 条「头变化归改契约的包」照此扩到这一对；SUB-055 的提交里就有这一行头变化。
